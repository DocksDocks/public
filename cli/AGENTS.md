# CLI and EngineNative (cli/)

The `docks-kit` CLI lives here: the Effect commands in `cli/src/`, the EngineNative
sync engine in `cli/src/engine-native/`, the bundled `docks-kit docs` topics in
`cli/docs/`, build and payload scripts in `cli/scripts/`, and the unit and golden
suites in `cli/test/`. Read this file before you edit a file under `cli/`.

## Conventions

### Module layout

| Path | Purpose |
|------|---------|
| `cli/build-binaries.sh` | Compiles the four release binaries (`docks-kit-linux-x64`, `docks-kit-linux-arm64`, `docks-kit-darwin-arm64`, `docks-kit-windows-x64.exe`). It checksums the four known artifact names rather than globbing `docks-kit-*`, so a packed `docks-kit-<version>.tgz` is never attested as a release binary. It stamps `cli/dist/VERSION` only when the directory holds one version, and on the next build discards every artifact that stamp attributes to a different version, because a launcher refuses to run one and keeping it makes `SHA256SUMS` span two versions. An artifact with no stamp has unknown provenance and may be a hand-built or downloaded recovery binary, so the script keeps it and warns; `--prune` discards those too. Nothing here removes an artifact the stamp vouches for. |
| `cli/src/engine-native/` | EngineNative implementation for `sync`, `model`, and `toolchain`; idempotent, flag-gated for destructive reconciliation |
| `cli/src/engine-native/ompSync.ts` | omp sync orchestration and summary |
| `cli/src/commands/omp.ts` | `docks-kit omp` session launcher: rejects model-selecting forwarded flags, checks the free catalog of each candidate profile, renders the free-model run overlay, and starts `omp launch` |
| `cli/src/checklistPrompt.ts` / `cli/src/terminalCells.ts` | Shared terminal checklist prompt on Effect's `Prompt.Custom`: items, a Save row, key hints, an ASCII fallback, and NO_COLOR; `docks-kit harnesses` uses it. `terminalCells.ts` measures text in terminal cells and rows from the pinned Unicode 18.0.0 East Asian Width table; derive the table again from a newer `EastAsianWidth.txt` the same way its header says |
| `cli/src/engine-native/ompOverlay.ts` | Free-model overlay render, omp argv and child environment, plus catalog parse and thinking-ceiling helpers |
| `cli/src/engine-native/scratch.ts` / `cli/src/commands/scratch.ts` | `docks-kit scratch new\|remove`: private agent temporary directories under `~/.cache/docks-kit/scratch/`; removal accepts only a real path strictly inside the scratch root, the system temporary directory, or `/var/tmp` |
| `cli/src/engine-native/tidy.ts` / `tidyReport.ts` / `cli/src/commands/tidy.ts` | `docks-kit tidy [--apply] [--repo <path>] [--report]`: plan and apply the safe leftover sweep (merged idle worktrees and their containers, orphaned processes in agent directories, idle scratch); `--apply` plans and applies under the lock `~/.cache/docks-kit/tidy-lock.db` (`commands/tidy.ts runTidy`); Docker calls run only against a verified local endpoint (`unix:///…` or `npipe:////./pipe/…`); the report is read-only |

| `cli/src/engine-native/kitLock.ts` | Only opener of the lock files: `~/.cache/docks-kit/tidy-lock.db` (`tidy --apply`), `sync-lock.db` (sync and `model` writes), and `<folder>/.docks-kit-sync-lock.db` (a Codex or agents folder that a sync writes). Each lock is an SQLite `BEGIN IMMEDIATE` transaction that the OS releases when its process ends; `node:` imports only |
| `cli/src/engine-native/processes.ts` | `processExited`: the shared PID liveness check (true only when `process.kill(pid, 0)` throws ESRCH); `atomicWrite.ts removeStaleTemporaries` and the macOS process list of `tidy.ts` use it |

### Engine and CLI rules

- **Idempotent operations.** Every EngineNative sync step must be safe to re-run. Settings merges, plugin installs, and marketplace adds are all idempotent — re-running with no SoT changes is a no-op.
- **Failed harness-CLI operations fail the sync.** A kit-managed marketplace or plugin command that exits non-zero is recorded through `failures.ts recordFailure` — it still warns in place, and `syncDispatch.ts engineSync, failure ledger` lists every entry under `--- Failures ---` after the summary, then returns exit 1. A skip is not a failure: a missing harness CLI, missing git, and a missing `SoT/toolchain.json` pin for Bun, `pi-intercom`, or an LSP package stay warn-only with exit 0; an unavailable plugin inventory warns without a ledger row and falls back to the full refresh, whose failed commands are recorded. A missing `skills-cli` pin is different: when `npx` is available and `SoT/.agents/skills.txt` names a skill that is not installed yet, `skillsInstall.ts skillsCli` aborts the universal-skills pass with exit 1, in a dry run too. `ompMarketplace.ts syncMarketplace, probe guard` returns before spawning so a host without omp never records one. Aggregate roll-up warnings (`N plugin operation(s) failed`) stay warns, because each counted site already records itself.
- **Removed bash engine.** The bash engine was removed after the `bash-engine-final` tag. `DOCKS_KIT_ENGINE=bash` must fail with the removed-engine message; engine bugs are fixed forward in EngineNative.
- **Effect 4 CLI stack.** The CLI pins `effect@4.1.2` (including `effect/cli`), `@effect/platform-bun@4.1.2` (`BunServices.layer`, `BunRuntime.runMain`), and `@effect/platform-node-shared@4.1.2`. `effect/cli`, `effect/Terminal`, `BunRuntime`, and `BunServices` carry `@stability unstable`, so a minor Effect release can break them; 4.1.0 added a required `Terminal.size`. Tests run on `vitest@5.1.0`, a plain devDependency. No GitHub advisory affects vitest 5.1.0: 5.0.3 fixed GHSA-qxg6-89mg-rqv8 and GHSA-xp26-3454-mjgp, and 5.0.0-rc.2 fixed GHSA-82fw-gwwq-j7x9. The lockfile resolves the `vite` peer to 7.3.7, which fixes the launch-editor and `server.fs.allow` advisories up to 7.3.6 and has no open advisory. `@effect/cli` and `@effect/platform` are removed and must not be reintroduced.
- **Effect skill routing.** Effect work in this checkout must verify migration and API call shapes against the installed declarations under `node_modules/effect/dist/cli/`, never from memory or a mutable dist-tag. The `effect-ts-setup`, `effect-ts-port`, and `effect-ts-specialist` skills target Effect 3.x and do not apply.
- **Per-machine harness selection.** The SQLite store `~/.docks-kit/kit.db` drives a flag-less sync. A missing selection selects `claude`, `codex`, and `agents`; it never selects `omp` implicitly. `sync` never prompts and never chooses a selection. `docks-kit harnesses` is the only command that chooses a selection. Any `withKitDb` opener, `sync` included, can import a legacy `state.json` selection into the `harness_selection` table once. With no stored selection, its picker pre-ticks all four harnesses, `omp` included, so a new machine opts out of omp instead of opting in; nothing changes until the picker saves. The same store holds the independent `omp_session` table, which only `docks-kit omp` writes, and a TTL cache (`cache_entry`) for the live Anthropic model list and `toolchain outdated` lookups. `kitDb.ts withKitDb` is the only opener: it runs the append-only `MIGRATIONS`, imports a legacy `state.json` once and renames it to `state.json.migrated`, and refuses a store from a newer schema. Cache rows carry the kit version as fingerprint, so a new release refetches them.
- **SOLID-aligned modules.** Axis modules own one concern each (see layout); orchestrators (`claudeSync.ts`, `codexSync.ts`, `skillsSync.ts`, `ompSync.ts`, `index.ts`, `argv.ts`, `parseArgs.ts`) keep prior exports. New shared shapes go in `sharedTypes.d.ts`, never a second local copy. The public CLI seam is `cli/src/engine.ts`.

### Engine behavior notes

- Codex `/import` can copy Claude hooks into `~/.codex/hooks.json`. `codexHooks.ts removeRetiredImportedHooks, legacy SessionStart cleanup` removes only recognized hooks from retired docks-kit Claude settings, backs up a changed file, and preserves user-authored hooks. Codex `/import` (codex-rs external-agent-migration `hooks_cla.rs`) skips a handler with keys outside `type`/`command`/`timeout`/`timeoutSec`/`statusMessage`/`async`, and it skips `async: true` handlers. Thus it imports neither the kit's exec-form (`args`) SessionStart handler nor its async Notification handler.
- Sync registers the `docks` marketplace. It installs or upgrades `docks@docks` and `plan-lifecycle@docks` at user scope. omp deletes the previous plugin folder on upgrade, so running omp sessions lose that plugin's agents. A test on omp 18.16.0 showed that `/reload-plugins` brings the agents back, and that `skill://` resolves to the new folder (#139). When an upgrade changes a version, `ompPlugins.ts syncPlugins, upgrade log` warns, sets the `ompPluginUpgraded` next-step trigger, and writes one event file into `~/.cache/docks-kit/omp-plugin-upgrades/`. The warning and the next step give one rule: run `/reload-plugins` in each running session, then read each plugin skill again through `skill://`. Restart omp instead when an upgraded plugin ships hooks, extension modules, or non-MCP tools, as the omp marketplace docs say. A version-changing upgrade does not set `ompRestart`. Each other plugin operation sets it: an install, a reinstall at the same version, an npm install, or a link. A changed kit plugin or config file also sets it. The restart next step then prints next to the upgrade rule. If the versions cannot be read after the upgrade, it warns once more, and each upgrade counts as a change to the version `unknown`. A failed write of the log only warns; it does not fail the sync. The log keeps the newest 100 event files; `cli/docs/sync-layers.md` gives the file format and the limits.
- Sync installs `pi-intercom` at the verified version from `SoT/toolchain.json`.

### `docks-kit omp` launcher

- `docks-kit omp [--model <selector>|--pick] [args...]` starts one interactive omp session. The overlay sets the 16 roles in `ompOverlay.ts ROLE_ORDER`, `judge` and `memory` included, to one free model, empties the 13 retry chains in `FALLBACK_ORDER`, and empties the chains keyed by the free model (bare, `off`, and every `THINKING_LADDER` level). Every other deployed chain stays as deployed. In particular, `modelRoles.web` and `retry.fallbackChains.web` keep the deployed web-search provider order. Thus a web search that falls through the `web/*` providers can reach the paid `openai-codex/gpt-6-luna` entry. It renders the overlay to `~/.cache/docks-kit/omp-free-<model>-<digest>.yml` (mode 0600). `ompOverlay.ts overlayFileName` gives each distinct model-and-level combination its own file, and the digest covers the selector and both levels. omp can re-read the overlay during a live session, so a second launcher with another model or level must not rewrite it. Deployed `~/.omp/agent/` files stay untouched, so the next plain `omp` run uses the paid configuration again.
- The launcher enforces the free model before omp starts. `omp.ts rejectedForwardedFlag` rejects a forwarded `--config`, `--model`, `--smol`, `--slow`, `--plan`, `--models`, `--provider`, `--prewalk-into`, or `--plan-yolo-into`, in both forms and also after a `--`, with exit 2 and a message that names the recoveries. `ompOverlay.ts buildOmpArgs` starts omp as `omp launch --config <overlay> --model <selector>[:<level>] [args...]`, so every forwarded word is message text, no omp subcommand runs through the launcher, and `--continue` or `--resume` keeps the free model. `ompOverlay.ts ompChildEnvironment` sets `PI_SMOL_MODEL`, `PI_SLOW_MODEL`, and `PI_PLAN_MODEL` to the free role values, and appends the overlay to `PI_CONFIG_FILES` so an `omp` that the bash tool of the session starts loads it too. The launcher prints one warning for each exported model variable that it replaces. In-session selection (`Alt+M`, `Alt+P`, `/switch`, `/model`, `/modelpreset`, `/resume`, a seance subagent), the `web` role, the model-kind roles `image`, `speech`, and `dictation`, and extensions and hooks stay outside the launcher. An `Alt+M` assignment of `default` writes `modelRoles.default` to the deployed `~/.omp/agent/config.yml`. `cli/docs/omp-models.md` lists these paths.
- The session model persists per machine in `~/.docks-kit/kit.db` (table `omp_session`), next to the harness selection. The default is `opencode-zen/muse-spark-1.3-contributor-free` at `xhigh`. Every launch, a plain launch included, runs `omp models --json` for the profile of the environment and `omp --profile <name> models --json` for each forwarded `--profile` value, and checks the remembered or default model against each live free catalog. When that model is not free in every one of these catalogs, the launcher stops with an error and does not start omp. `--model` and `--pick` resolve against the catalog of the last forwarded profile. `ompOverlay.ts ladderCeiling, advisorLevelFor` derive both levels from the ladder of the chosen model for the `--model` path, and `ompOverlay.ts planEffortChoice` drives the `--pick` wizard, which asks whether every role shares one level and otherwise takes one level for the main roles and one for the advisor from that model's own ladder. Levels never come from a fixed list: free ladders are not uniform, three free models publish no `medium`, and two publish no ladder, which the overlay renders as bare selectors. The picker lists only catalog models at zero input and output cost with `pricingStatus` free or unknown.
- `docks-kit omp --fast` toggles `tier.openai` in the deployed `~/.omp/agent/config.yml` between `priority` (omp's `/fast on` tier for OpenAI and OpenAI-Codex models) and `none`, prints the change, and exits. `ompFastMode.ts toggleOpenAiFast` edits only that key. `SoT/.omp/config.yml` does not declare `tier.openai`, so the additive merge keeps the toggled value across sync. The four review agents inherit the live tier of the main session, so they follow the toggle in a new session; a running session keeps its tier. `--fast` never changes the Anthropic tier, and sync sets the deployed `tier.anthropic` to the SoT value `none`, so each session starts with it. `/fast on` in an Opus session sets `anthropic: priority` for that session, and the reviewers and their Opus fallback inherit it; omp has no override that inherits only the OpenAI tier. There is no Ultrafast flag: omp ignores `ultrafast` for a Codex model whose catalog `serviceTiers` omits it, and the current GPT models omit it.

### Test suites

The spawning suites launch a prebuilt bundle of `cli/src/main.ts`. The build runs once per run, into the ignored `cli/dist-test/`. Bun otherwise transpiles the whole CLI on every child spawn. Set `DOCKS_KIT_TEST_CLI_ENTRY=<repo>/cli/src/main.ts` to run those suites against the TypeScript entry. Use that variable to read a real stack trace. See `cli/test/lib/cliEntry.ts`.

## Gotchas

- The launchers skip a `cli/dist/` binary when any file under `cli/src/` or `cli/docs/` is newer than the binary, a Markdown file included. Keep instruction files out of those two trees (verify: `grep -n 'scan_dir' docks-kit`; probe: `cli/test/unit/launcher.test.ts` plants a newer `cli/docs/overview.md` and asserts the warning).
- `package.json` `files` publishes `cli/src` and `cli/docs`, so a file there ships in the npm package (verify: `jq .files package.json`).
- `format:check` runs `bun fmt` on `cli/src`, `cli/test`, and `cli/scripts`, and `bun fmt` also checks Markdown (probe: `bun fmt --no-script --check AGENTS.md` reports the root file).

Pointers here name concepts, not coordinates — if a path or symbol moved,
trust the stated purpose and re-locate it (grep the symbol) before acting.
