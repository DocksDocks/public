# CLI and EngineNative (cli/)

The `docks-kit` CLI lives here: the Effect commands in `cli/src/`, the EngineNative
sync engine in `cli/src/engine-native/`, the bundled `docks-kit docs` topics in
`cli/docs/`, build and payload scripts in `cli/scripts/`, and the unit and golden
suites in `cli/test/`. Read this file before you edit a file under `cli/`.

## Conventions

### Module layout

| Path | Purpose |
|------|---------|
| `cli/build-binaries.sh` | Compiles the four release binaries (`docks-kit-linux-x64`, `docks-kit-linux-arm64`, `docks-kit-darwin-arm64`, `docks-kit-windows-x64.exe`). It checksums the four known artifact names rather than globbing `docks-kit-*`, so a packed `docks-kit-<version>.tgz` is never attested as a release binary. It stamps `cli/dist/VERSION` only when the directory holds one version, and on the next build discards every artifact that stamp attributes to a different version, because a launcher refuses to run one and keeping it makes `SHA256SUMS` span two versions. An artifact with no stamp has unknown provenance and may be a hand-built or downloaded recovery binary, so the script keeps it and warns; `--prune` discards those too. Nothing here removes an artifact the stamp vouches for. |
| `cli/src/engine-native/` | EngineNative implementation for `sync` and `toolchain`; idempotent |
| `cli/src/engine-native/ompSync.ts` | omp sync orchestration and summary |
| `cli/src/commands/omp.ts` | `docks-kit omp` session launcher: rejects model-selecting forwarded flags, checks the free catalog of each candidate profile, renders the free-model run overlay, and starts `omp launch` |
| `cli/src/engine-native/ompOverlay.ts` | Free-model overlay render, omp argv and child environment, plus catalog parse and thinking-ceiling helpers |
| `cli/src/engine-native/scratch.ts` / `cli/src/commands/scratch.ts` | `docks-kit scratch new\|remove`: private agent temporary directories under `~/.cache/docks-kit/scratch/`; removal accepts only a real path strictly inside the scratch root, the system temporary directory, or `/var/tmp` |
| `cli/src/engine-native/tidy.ts` / `tidyReport.ts` / `cli/src/commands/tidy.ts` | `docks-kit tidy [--apply] [--repo <path>] [--report]`: plan and apply the safe leftover sweep (merged idle worktrees and their containers, orphaned processes in agent directories, idle scratch); `--apply` plans and applies under the lock `~/.cache/docks-kit/tidy-lock.db` (`commands/tidy.ts runTidy`); Docker calls run only against a verified local endpoint (`unix:///…` or `npipe:////./pipe/…`); the report is read-only |
| `cli/src/engine-native/ompKitPlugin.ts` | Materializes the `SoT/.omp/plugin/` payload to `~/.docks-kit/omp-plugin` with the kit version; `ompPlugins.ts syncPlugins` links it |
| `cli/src/engine-native/<axis>.ts` | One change axis per file: `parseHelp`, `ompFileDeploy`/`ompPlugins`, `engineCtx`/`syncConcurrency`/`syncDispatch`; orchestrators keep prior exports |
| `cli/src/engine-native/sharedTypes.d.ts` | Single definition per shared shape (JSON object, omp session model, fetch signature) |
| `cli/src/engine-native/kitDb.ts` | Only opener of the SQLite store `~/.docks-kit/kit.db`: append-only migrations, one-time `state.json` import, TTL cache |
| `cli/src/engine-native/kitLock.ts` | Only opener of the lock files: `~/.cache/docks-kit/tidy-lock.db` (`tidy --apply`), `sync-lock.db` (sync and `omp --fast`), and `<folder>/.docks-kit-sync-lock.db` (an omp folder that a sync or `omp --fast` writes). Each lock is an SQLite `BEGIN IMMEDIATE` transaction that the OS releases when its process ends; `node:` imports only |
| `cli/src/engine-native/processes.ts` | `processExited`: the shared PID liveness check (true only when `process.kill(pid, 0)` throws ESRCH); `atomicWrite.ts removeStaleTemporaries` and the macOS process list of `tidy.ts` use it |
| `cli/test/fixtures/` | Golden fixtures: `home-fresh`, `home-drift` |

### Engine and CLI rules

- **Idempotent operations.** Every EngineNative sync step must be safe to re-run. Settings merges, plugin installs, and the retirement of the former marketplace plugins are all idempotent — re-running with no SoT changes is a no-op.
- **Failed harness-CLI operations fail the sync.** A kit-managed plugin or marketplace-removal command that exits non-zero is recorded through `failures.ts recordFailure` — it still warns in place, and `syncDispatch.ts engineSync, failure ledger` lists every entry under `--- Failures ---` after the summary, then returns exit 1. A skip is not a failure: a missing harness CLI, missing git, and a missing `SoT/toolchain.json` pin for Bun or `pi-intercom` stay warn-only with exit 0; an unavailable plugin inventory warns without a ledger row, skips the retirement of the former marketplace plugins, and gives `pi-intercom` and the kit plugin the full refresh path, whose failed commands are recorded. `ompPlugins.ts syncPlugins` probes omp and git before it spawns, so a host without them never records one. Aggregate roll-up warnings (`N plugin operation(s) failed`) stay warns, because each counted site already records itself.
- **Removed bash engine.** The bash engine was removed after the `bash-engine-final` tag. `DOCKS_KIT_ENGINE=bash` must fail with the removed-engine message; engine bugs are fixed forward in EngineNative.
- **Effect 4 CLI stack.** The CLI pins `effect@4.1.2` (including `effect/cli`), `@effect/platform-bun@4.1.2` (`BunServices.layer`, `BunRuntime.runMain`), and `@effect/platform-node-shared@4.1.2`. `effect/cli`, `effect/Terminal`, `BunRuntime`, and `BunServices` carry `@stability unstable`, so a minor Effect release can break them; 4.1.0 added a required `Terminal.size`. Tests run on `vitest@5.1.0`, a plain devDependency. No GitHub advisory affects vitest 5.1.0: 5.0.3 fixed GHSA-qxg6-89mg-rqv8 and GHSA-xp26-3454-mjgp, and 5.0.0-rc.2 fixed GHSA-82fw-gwwq-j7x9. The lockfile resolves the `vite` peer to 7.3.7, which fixes the launch-editor and `server.fs.allow` advisories up to 7.3.6 and has no open advisory. `@effect/cli` and `@effect/platform` are removed and must not be reintroduced.
- **Effect skill routing.** Effect work in this checkout must verify migration and API call shapes against the installed declarations under `node_modules/effect/dist/cli/`, never from memory or a mutable dist-tag. The `effect-ts-setup`, `effect-ts-port`, and `effect-ts-specialist` skills target Effect 3.x and do not apply.
- **Kit store.** The SQLite store `~/.docks-kit/kit.db` holds the `omp_session` table, which only `docks-kit omp` writes (`ompSession.ts`), and a TTL cache (`cache_entry`) for `toolchain outdated` lookups. Sync never opens kit.db. The `harness_selection` table has had no use since 0.24.0 and stays in `MIGRATIONS[0]` only to keep schema 1. `kitDb.ts withKitDb` is the only opener: it runs the append-only `MIGRATIONS`, imports a legacy `state.json` session model once and renames the file to `state.json.migrated`, and refuses a store from a newer schema. Cache rows carry the kit version as fingerprint, so a new release refetches them.
- **SOLID-aligned modules.** Axis modules own one concern each (see layout); orchestrators (`ompSync.ts`, `index.ts`, `argv.ts`, `parseArgs.ts`) keep prior exports. New shared shapes go in `sharedTypes.d.ts`, never a second local copy. The public CLI seam is `cli/src/engine.ts`.

### Engine behavior notes

- The kit plugin ships the docks and plan-lifecycle content, so sync installs no plugin from the `docks` marketplace. Each real sync retires the former marketplace plugins in `ompPlugins.ts retireMarketplacePlugins`, after the inventory read and before the `pi-intercom` install and the kit plugin link. For each of `docks@docks` and `plan-lifecycle@docks` with a `scope: "user"` inventory row, it runs `omp plugin uninstall --scope user <id>`. For each `scope: "project"` row of these ids, it warns with the manual command `omp plugin uninstall --scope project <id>`, to run from that project, and it changes nothing in that project. When no user uninstall failed, it runs `omp plugin marketplace remove docks` if the active registry (`<data root>/marketplaces.json`) lists `docks`, or if no active registry exists and the legacy registry (`<config root>/marketplaces.json`) lists it (`registryListsDocks`). omp copies the legacy registry only when no active registry exists, so a legacy entry beside an active registry is stale and starts no command. When the inventory cannot be read, the sync warns and skips the retirement; the next sync tries again. A failed uninstall or removal goes to the failure ledger with the manual command. `--skip-plugin-refresh` does not skip the retirement. Each real sync also removes the folder `~/.cache/docks-kit/omp-plugin-upgrades/` of the retired plugin upgrade log when it exists. Each uninstall sets `ompRestart`, because the retired plugins ship extensions; an npm install, a link, and a changed kit plugin or config file also set it. A dry run prints `[dry-run] omp plugin uninstall --scope user <id>` for both ids, and `[dry-run] omp plugin marketplace remove docks` when a registry lists `docks`. `cli/docs/sync-layers.md` gives the summary line and the warnings.
- Sync installs `pi-intercom` at the verified version from `SoT/toolchain.json`.

### `docks-kit omp` launcher

- `docks-kit omp [--model <selector>|--pick] [args...]` starts one interactive omp session. The overlay sets the 16 roles in `ompOverlay.ts ROLE_ORDER`, `judge`, `memory`, and `advisor` included, to one free model at one level, empties the 12 retry chains in `FALLBACK_ORDER`, and empties the chains keyed by the free model (bare, `off`, and every `THINKING_LADDER` level). Every other deployed chain stays as deployed. In particular, `modelRoles.web` and `retry.fallbackChains.web` keep the deployed web-search provider order. Thus a web search that falls through the `web/*` providers can reach the paid `openai-codex/gpt-6-luna` entry. It renders the overlay to `~/.cache/docks-kit/omp-free-<model>-<digest>.yml` (mode 0600). `ompOverlay.ts overlayFileName` gives each distinct model-and-level combination its own file, and the digest covers the selector and the level. omp can re-read the overlay during a live session, so a second launcher with another model or level must not rewrite it. Deployed `~/.omp/agent/` files stay untouched, so the next plain `omp` run uses the paid configuration again.
- The launcher enforces the free model before omp starts. `omp.ts rejectedForwardedFlag` rejects a forwarded `--config`, `--model`, `--smol`, `--slow`, `--plan`, `--models`, `--provider`, `--prewalk-into`, or `--plan-yolo-into`, in both forms and also after a `--`, with exit 2 and a message that names the recoveries. `ompOverlay.ts buildOmpArgs` starts omp as `omp launch --config <overlay> --model <selector>[:<level>] [args...]`, so every forwarded word is message text, no omp subcommand runs through the launcher, and `--continue` or `--resume` keeps the free model. `ompOverlay.ts ompChildEnvironment` sets `PI_SMOL_MODEL`, `PI_SLOW_MODEL`, and `PI_PLAN_MODEL` to the free role values, and appends the overlay to `PI_CONFIG_FILES` so an `omp` that the bash tool of the session starts loads it too. The launcher prints one warning for each exported model variable that it replaces. In-session selection (`Alt+M`, `Alt+P`, `/switch`, `/model`, `/modelpreset`, `/resume`, a seance subagent), the `web` role, the model-kind roles `image`, `speech`, and `dictation`, and extensions and hooks stay outside the launcher. An `Alt+M` assignment of `default` writes `modelRoles.default` to the deployed `~/.omp/agent/config.yml`. `cli/docs/omp-models.md` lists these paths.
- The session model persists per machine in `~/.docks-kit/kit.db` (table `omp_session`). The default is `opencode-zen/muse-spark-1.3-contributor-free` at `xhigh`. Every launch, a plain launch included, runs `omp models --json` for the profile of the environment and `omp --profile <name> models --json` for each forwarded `--profile` value, and checks the remembered or default model against each live free catalog. When that model is not free in every one of these catalogs, the launcher stops with an error and does not start omp. `--model` and `--pick` resolve against the catalog of the last forwarded profile. `ompOverlay.ts ladderCeiling` derives the level from the ladder of the chosen model for the `--model` path. `ompOverlay.ts planEffortChoice` drives the `--pick` wizard, which asks one level for every role from that model's own ladder. The overlay keeps `modelRoles.advisor` on the free model, because omp resolves `/advisor on` from that role before `slow`. Levels never come from a fixed list: free ladders are not uniform, three free models publish no `medium`, and two publish no ladder, which the overlay renders as bare selectors. The picker lists only catalog models at zero input and output cost with `pricingStatus` free or unknown.
- `docks-kit omp --fast` toggles `tier.openai` in the deployed `~/.omp/agent/config.yml` between `priority` (omp's `/fast on` tier for OpenAI and OpenAI-Codex models) and `none`, prints the change, and exits. `ompFastMode.ts toggleOpenAiFast` edits only that key. `SoT/.omp/config.yml` does not declare `tier.openai`, so the additive merge keeps the toggled value across sync. The four review agents inherit the live tier of the main session, so they follow the toggle in a new session; a running session keeps its tier. `--fast` never changes the Anthropic tier. The SoT leaves `tier.anthropic` at omp's default `none`, so each session starts with it. `/fast on` in an Opus session sets `anthropic: priority` for that session, and the reviewers and their Opus fallback inherit it; omp has no override that inherits only the OpenAI tier. There is no Ultrafast flag: omp ignores `ultrafast` for a Codex model whose catalog `serviceTiers` omits it, and the current GPT models omit it.

### Test suites

The spawning suites launch a prebuilt bundle of `cli/src/main.ts`. The build runs once per run, into the ignored `cli/dist-test/`. Bun otherwise transpiles the whole CLI on every child spawn. Set `DOCKS_KIT_TEST_CLI_ENTRY=<repo>/cli/src/main.ts` to run those suites against the TypeScript entry. Use that variable to read a real stack trace. See `cli/test/lib/cliEntry.ts`.

## Gotchas

- The launchers skip a `cli/dist/` binary when any file under `cli/src/` or `cli/docs/` is newer than the binary, a Markdown file included. Keep instruction files out of those two trees (verify: `grep -n 'scan_dir' docks-kit`; probe: `cli/test/unit/launcher.test.ts` plants a newer `cli/docs/overview.md` and asserts the warning).
- `package.json` `files` publishes `cli/src` and `cli/docs`, so a file there ships in the npm package (verify: `jq .files package.json`).
- `format:check` runs `bun fmt` on `cli/src`, `cli/test`, and `cli/scripts`, and `bun fmt` also checks Markdown (probe: `bun fmt --no-script --check AGENTS.md` reports the root file).

Pointers here name concepts, not coordinates — if a path or symbol moved,
trust the stated purpose and re-locate it (grep the symbol) before acting.
