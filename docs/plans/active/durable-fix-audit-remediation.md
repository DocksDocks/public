## Goal

Every defect the thirteen-slice durability audit proved is fixed at its cause, and the golden gate can no longer report success without comparing anything

Mode: plan-and-implement

## Research

The audit ran in two waves, both fanned out in parallel.

**Wave 1 — thirteen read-only reviewers**, one per disjoint slice, covering all 8126 lines of `cli/src`, `cli/test`, `cli/scripts`, `SoT/.claude/bin`, and the three shell files. They produced 79 claims. A global marker sweep found **zero** `TODO`, `FIXME`, `HACK`, `XXX`, `@ts-ignore`, `@ts-expect-error`, or `eslint-disable` occurrences in tracked source; the only `temporar*` hits are the identifiers `temporaryDir` and `temporaryDirs` in the golden harness. There is no marker-comment debt. Every defect below is behavioral.

**Wave 2 — eleven reproduction agents.** A claim is not a fact, so each of the 79 was executed rather than re-read: triggering input constructed in a throwaway `HOME`, the real code path run, the output recorded. This changed the picture materially and is the reason the register below is trustworthy:

- **2 claims were REFUTED** and are excluded from this plan. They are listed after the register so a later reader does not resurrect them.
- **6 were RECLASSIFIED.** The most instructive is F04: the original claim said three CLI modifiers were unhandled. They are in fact fully parsed and validated at `parseArgs.ts:188-196,240-248`. The real defect is narrower — only the deselected-target *warning* is missing. Same file, different fix. Implementing the claim as written would have been a false fix.
- **10 are LATENT:** real in the code, unreachable from any entry point today. They are kept, tiered last, and marked, because the reachability that protects them is incidental rather than designed.
- **28 confirmed rows re-ranked to HIGH**, up from 8 in wave 1. Reproduction escalated more than it demoted: several rows filed as cosmetic turned out to lose data or report success over work that never happened.

Reproduction highlights that set the priority order:

- `codexSync.ts` merges TOML line by line. A user config whose table header carries a trailing comment, an inner space, or CRLF line endings — all legal TOML — is not matched by the byte-equality removal, yet the SoT block is appended unconditionally. The result defines a table twice and `~/.codex/config.toml` stops parsing. This is silent corruption of a file the kit does not own.
- `golden-mutation.ts:688` seeds its mismatch counter with `invariantFailures`. `.github/workflows/parity.yml` gates CI by grepping for the `prove-red OK` string that counter controls, so an unrelated invariant failure satisfies the proof that the comparator can still detect a planted mismatch. The sibling suite `golden-dryrun.ts:176` seeds the same counter with `0`, so this is divergence, not intent.
- `engine.ts:61-64` warns on a failed child and then returns its stdout anyway, so `docks-kit status --json` emits a well-formed document with an empty toolchain table and exits 0 while nothing was inspected.
- `docks-kit:33` reads the binary version with `IFS= read -r ... < <(... || true)`. The `|| true` guards the binary inside the process substitution, not `read`, which returns non-zero on empty input and terminates the launcher under `set -euo pipefail` — so the stale-binary fallback on the next line is unreachable in precisely the case it exists for.
- `skillsSync.ts:190` unlinks the destination before checking whether it is the source, so `linkOrCopy(x, x)` deletes a real file and leaves a self-referential symlink.

One register row contradicts an existing test, and the plan resolves it rather than leaving it to the implementer. `cli/test/unit/notify.test.mjs:53-63` asserts `main()` returns `7` when the selected player exits `7`, under the title "returns a selected player failure without falling through". `vitest.config.ts` includes `cli/test/unit/**/*.test.{ts,mjs}`, so that assertion runs inside `test:unit` and would make acceptance A1 unreachable. F53 is the intended contract and the test is the pre-fix behavior written down: `step:notify_hook` re-pins the expectation from `7` to `0` and renames the case, while keeping `expect(spawnSync).toHaveBeenCalledTimes(1)` — the no-fall-through property is correct and stays; only the propagated exit code changes.
